# Project brief

Status: UNFILLED. This is the input to planning, not an approved specification.

## Identity

Project name, owner, decision-maker and intended audience.

## Problem

What happens today? Who is affected? What evidence shows the problem matters? What alternatives already exist?

## Three concrete journeys

For each: actor, starting state, action, successful result, failure case and needed permissions. Include an operator/support journey if the product needs one.

## Scope

First-release outcomes; explicit exclusions; later possibilities. Separate must-have requirements from suggestions.

## Constraints

Budget, date, team skills, supported platforms/devices, accessibility needs, network conditions, data sensitivity, location/retention constraints, existing integrations and mandated technologies.

## Success

Observable user outcomes and how they will be measured. Avoid substituting “uses AI” or a list of frameworks for a user outcome.

## Inputs and authority

Link contracts, client documents, research, existing systems and UI references. Mark each as binding, advisory or inspiration. Record actual approvals separately.

## Unknowns

List decisions that need research or owner input. Continue independent planning while blockers are being resolved.
