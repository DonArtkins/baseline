# Observability and operations

Define the signals needed to diagnose the actual product: request correlation, structured errors, latency, availability, queue depth or model/tool outcomes where applicable. Identify sensitive fields and redaction rules before collecting logs.

For each alert, name a user-impacting symptom, threshold/window, owner, runbook and recovery check. Avoid alerts nobody can act on. Record incident evidence in a sanitized bug/incident record and feed recurring causes into planning.
