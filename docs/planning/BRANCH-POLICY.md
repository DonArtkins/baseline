# Branch and worktree policy

## New feature

Preserve local changes. Fetch the configured remote/default branch. Create `feature/<area>/<NN>-<slug>` from its current tip; use a separate worktree if switching would disturb existing work. Use `fix/` for a bug tied to the same owning spec and `docs/` for planning-only work. The root coordination area is named `root`. Area names are free-form (target's own words, e.g. `app`, `api`).

Example:

```sh
git fetch origin
git switch -c feature/api/02-account-endpoint origin/main
```

Do not checkout and pull over someone else's dirty worktree. Do not create a feature from another feature branch. A dependency that has not merged blocks dependent production work. A branch provenance check can detect some shared unmerged commits; it cannot prove how every branch was originally created.

## Bootstrap exception

A repository with no commits has no default-branch history to branch from. Make one reviewed initial planning/template snapshot. The local gate allows this only in template/planning phase with no production source. Subsequent changes follow named branches. Creating a remote, pushing or changing repository protection requires the user's authorization.

## During the feature

Scope the branch to one feature in the target's `.baseline/change.json` (per-project state, generated by `configure.py`). Contract documentation may span areas; keep production changes within the owning area. Review fixes stay on this branch. Commit the owning tracker with the work and run branch checks before push. Merge target is the configured default branch.

## Completion

Report verified behavior, tests and open operator gates. Wait for the user's merge/next-feature decision if that is their chosen workflow; existing explicit authorization remains valid. After merge, fetch before starting the next spec.

The first planning/template commit may also be pushed from the default branch when no remote default ref exists locally and HEAD has exactly one commit. This bootstrap exception never permits production source. Later pushes require normal feature scope and a fetched comparison ref.
