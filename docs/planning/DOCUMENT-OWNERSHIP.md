# One fact, one home

| Fact | Owner | Other files do this |
|---|---|---|
| Product requirement | Product context and linked requirement ID | Link the requirement |
| Runtime/SDK choice | Stack contract | Link approved version |
| System responsibility | System map | Add local detail only |
| Interface shape | Canonical contract | Link version and consumer behavior |
| Feature delivery state | Owning progress tracker | Link status row |
| Dependency order and reason | Roadmap | Render concise tracker chain |
| Decision and alternatives | ADR | Link decision |
| Token value | UI token context | Reference semantic token |
| Reproduction and regression | Bug record | Link evidence |
| Review disposition | Review record | Link finding |
| Approval | Approval register | Link scope/version |

Agent files are routing and policy documents. They should not accumulate delivery narratives. Aim for short context files that are useful in one reading; split by ownership when detail grows. Historical facts remain dated and clearly superseded. Generated indexes may mirror identifiers, but must never become independent status authorities.
