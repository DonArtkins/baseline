# Documentation map

| Folder | Canonical responsibility |
|---|---|
| `planning/` | Workflow, approvals, dependency order, risks and change rules |
| `decisions/` | Why a consequential choice was made |
| `architecture/` | Boundaries, flows, scaling and failure modes |
| `contracts/` | Owned interfaces and consumer mappings |
| `api/` | API usage and examples when an API exists |
| `database/` | Data model, retention, migrations and restore |
| `design/` | Reference synthesis, tokens, components, content and accessibility |
| `security/` | Threat model and concrete security verification |
| `deployment/` | Environment matrix, release, rollback and operations |
| `observability/` | Signals, alerts, incident diagnosis and redaction |
| `testing/` | Verification strategy and release evidence |
| `tooling/` | Hooks, CI, skills and version records |
| `meta/` | Template provenance and validation limits |

Fill project-specific documents after discovery. A document's existence does not imply approval or implementation. Keep the README as a map rather than a second progress tracker.
