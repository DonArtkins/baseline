# Contributing

Read `AGENTS.md`, the owning system kit and current spec. Follow [branch policy](docs/planning/BRANCH-POLICY.md), preserve unrelated work, and keep each PR focused on one reviewed outcome.

Include the user-visible result, acceptance evidence, contract changes, deviations and open operator gates. Update the tracker before push. Use the PR template and resolve review findings with reasoning and tests. Never include reference repositories' private content or copied licensed assets without permission.
