# UI inspiration library

Collect references for a specific user journey or surface, not simply attractive screenshots. Use [Dribbble](https://dribbble.com/) and the user-recommended [@marcelkargul on X](https://x.com/marcelkargul) as discovery starting points. The account's content was not accessible during template preparation; no specific post or visual style is attributed here.

## Capture

Save a permitted screenshot with a descriptive filename under `references/`, then add a record in [the catalog](CATALOG.md). Include creator, original post URL, date, viewport, surface, what to borrow, what to reject and reuse status. A source link alone is not a design specification.

## Synthesize

Follow [from inspiration to system](../docs/design/FROM-INSPIRATION-TO-SYSTEM.md). Pick a canonical layout direction for each surface. Supporting references can contribute individual patterns; record their role rather than mixing incompatible systems indiscriminately.

## Apply

Feature specs link the chosen reference IDs, approved wireframes and component/token contracts. Implement original product content and interactions. Do not copy logos, illustrations, premium assets or product identities without appropriate rights. Keep proof that each requested surface and state was reviewed.
