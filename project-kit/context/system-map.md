# System map

Status: UNFILLED. Areas are free-form per target project (recorded in that target's `.baseline/project.json`, generated by `scripts/configure.py`; the template master has no `.baseline/`).

## Ownership table

For each selected system, name its responsibility, owned data, public interfaces, upstream dependencies and deployment unit. Distinguish a folder from a separately deployed service; a monorepo does not require microservices.

## Data and trust flow

Create an architecture diagram with actors, entrypoints, trust boundaries, data stores and external providers. Show who authorizes each write. Link canonical contracts rather than repeating their payloads.

## System selection

Use the smallest split that supports the product. A static site need not invent an API; a CLI need not invent a mobile app. Name areas in the target's own words (e.g. "app, api, db"). `infra/` and `qa/` kits here are optional references, not prerequisites.

## Governance

Link each kit's AGENTS entrypoint and tracker. Amend this map when responsibility moves; update affected consumers before implementation.
